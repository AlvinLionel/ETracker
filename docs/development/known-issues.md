# ETracker — Known Issues and Open Questions

**Last reviewed:** 2026-11-12

This list reflects repository review on the date above. “Confirmed” means the limitation or defect is visible in current code. “Needs verification” means available evidence is insufficient to close it. Product and architecture choices remain subject to the decision log; recording a question here does not approve a change.

## Confirmed defects and risks

| ID | Area | Finding and impact | Evidence / next action | Status |
|---|---|---|---|---|
| KI-002 | Forecast scheduling | Scheduled generation runs when enabled settings are saved and during app startup. It uses a unique UTC `scheduled_month`, so retries that month are idempotent. If the app misses a month, next startup generates only for the current month; it does not backfill missed months. | `src-tauri/src/persistence/forecasting.rs`, `generate_scheduled_if_due`; behavior is explicitly approved. | Documented limitation |
| KI-004 | Local file privacy | Expired statement-source BLOBs are deleted at startup with SQLite `secure_delete=ON` and a best-effort WAL truncate checkpoint. Transaction attachments are stored as ordinary files in application-managed storage and are not encrypted at rest; user removal cannot guarantee physical erasure from filesystem snapshots or SSD media. Encrypted backups include the database and attachments. Local database encryption and at-rest attachment protection remain open. | `src-tauri/src/infrastructure/database/connection.rs`, `src-tauri/src/persistence/attachments.rs`, `src-tauri/src/persistence/backup.rs`; review deletion and at-rest protection before broader distribution (`DB-032`). | Partially addressed — open security/privacy verification |
| KI-005 | Diagnostics | Settings can download a redacted support report with app/platform versions and database health status; detailed integrity output remains local in Settings. Persistent structured logs and a retention policy are not implemented, and some Tauri commands still translate persistence failures to generic user errors. | `src-tauri/src/persistence/diagnostics.rs`, `src-tauri/src/persistence/integrity.rs`; persistent logging and retention remain pending (`PEND-028`). | Partially implemented — open |

## Scope, behavior and decision questions

| ID | Question or uncertainty | Evidence and required confirmation |
|---|---|---|
| Q-001 | Legacy non-KES display behavior | KES-only new-write enforcement is implemented for planning and forecasts. Existing non-KES rows are retained and subscription projections show separate currency totals without conversion. Verify future screens preserve this separation; never sum these values. |
| Q-003 | Forecast scheduling cadence | Approved behavior is opt-in checks on setting save and app startup, UTC calendar month, one scheduled snapshot/month, no backfill. Operational limitation: a month is skipped if the application is never started during it. |
| Q-004 | Is duplicate detection’s conservative rule sufficient? | Resolved by `DB-035`: exact account/date/type/amount is a candidate signal only, never an automatic suppression. Provider references and fuzzy matching are deferred until verified sample formats exist. |
| Q-005 | What should happen to pending transactions during reconciliation? | Still pending (`PEND-004`). Current staged format assumes reviewed posted rows. |
| Q-006 | What are the full savings goal/contribution semantics? | Implemented manual and linked-transfer contributions; exact relationship remains listed pending (`PEND-007`). Verify withdrawals, corrections and goal/account balance expectations before extending. |
| Q-007 | What is the policy for discarding/cancelling import batches? | Resolved by `DB-034`: unfinished workspaces can be discarded and made read-only; history and source bytes remain until the approved 90-day expiry cleanup. Finalized batches cannot be discarded. |

## Resolved items removed from the old outstanding list

The earlier entries for planning, analytics and forecasting were stale: budgets, savings, subscriptions, analytics, local forecasts and forecast evaluation now exist and have tests. The former OW-010 is resolved: budget plans load into the template editor; account-list CSV/Excel rows are reviewed in Accounts and safely create new KES accounts, with account numbers ignored, duplicate pairs and unsupported currencies excluded. Tests cover dated balances and classification of dated account lists versus statements. KI-003 and Q-002/Q-008 are resolved by `DB-033`: linked refunds appear in both their own and their original expense's audit histories, with receipt, void and reversal recorded atomically. The unused `formatKES` TypeScript compiler error was fixed. CSV formula-prefix protection was added for untrusted text columns while preserving negative numeric amounts and quote escaping. These are not open issues; broader release verification remains.

## Configuration review still required

Review CSP against all shipped views/assets, app identity, default icons, `.gitignore`, dev/production configuration, dependency/lockfile maintenance, sensitive-data logging, import/backup size limits, and local database protection before release. Backups are encrypted, but local database encryption at rest is not implemented. A restrictive production CSP has been configured; runtime desktop verification remains outstanding. The codebase has no runtime HTTP/fetch client or external service call sites in the reviewed application paths, but disconnected-machine behavior still needs a desktop smoke test. These are review items, not confirmed failures except where explicitly identified above.
