# ETracker — Known Issues and Open Questions

**Last reviewed:** 2026-11-13

This list reflects repository review on the date above. “Confirmed” means the limitation or defect is visible in current code. “Needs verification” means available evidence is insufficient to close it. Product and architecture choices remain subject to the decision log; recording a question here does not approve a change.

## Confirmed defects and risks

| ID | Area | Finding and impact | Evidence / next action | Status |
|---|---|---|---|---|
| KI-002 | Forecast scheduling | Scheduled generation runs when enabled settings are saved and during app startup. It uses a unique UTC `scheduled_month`, so retries that month are idempotent. If the app misses a month, next startup generates only for the current month; it does not backfill missed months. | `src-tauri/src/persistence/forecasting.rs`, `generate_scheduled_if_due`; behavior is explicitly approved. | Documented limitation |
| KI-004 | Local file privacy | The live database is encrypted with SQLCipher using a random key protected by current-user Windows DPAPI. Attachment files use AES-GCM; legacy database and attachment migration runs on startup. Encrypted passphrase backups are the recovery path if the Windows profile or key is lost. Opening an attachment creates a temporary decrypted copy, removed on next startup or by the Settings cleanup action. Physical erasure of old file-system blocks, snapshots or SSD media cannot be guaranteed. | `src-tauri/src/infrastructure/database/connection.rs`, `src-tauri/src/infrastructure/security.rs`, `src-tauri/src/persistence/attachments.rs`, and `src-tauri/src/persistence/backup.rs`; still verify installer build and upgrade/restore on a clean Windows profile. | Implemented; clean-profile release verification remains |
| KI-005 | Diagnostics | Settings can save a support report with environment/database health and up to 100 recent allowlisted app events. Event labels contain no free-form data and expire after 30 days; reports are user-selected and never sent automatically. Detailed integrity output remains local in Settings. | `src-tauri/src/persistence/diagnostics.rs`, `src-tauri/src/commands/backup.rs`, and `src/features/settings/SettingsPage.tsx`; generic user-facing errors still limit troubleshooting for some unrelated commands. | Redacted local event history implemented; generic command errors remain |

## Scope, behavior and decision questions

| ID | Question or uncertainty | Evidence and required confirmation |
|---|---|---|
| Q-001 | Legacy non-KES display behavior | KES-only new-write enforcement is implemented for planning and forecasts. Existing non-KES rows are retained and subscription projections show separate currency totals without conversion. Verify future screens preserve this separation; never sum these values. |
| Q-003 | Forecast scheduling cadence | Approved behavior is opt-in checks on setting save and app startup, UTC calendar month, one scheduled snapshot/month, no backfill. Operational limitation: a month is skipped if the application is never started during it. |
| Q-004 | Is duplicate detection’s conservative rule sufficient? | Resolved by `DB-035`: exact account/date/type/amount is a candidate signal only, never an automatic suppression. Provider references and fuzzy matching are deferred until verified sample formats exist. |
| Q-005 | What should happen to pending transactions during reconciliation? | Still pending (`PEND-004`). Current staged format assumes reviewed posted rows. |
| Q-006 | What are the full savings goal/contribution semantics? | Resolved for the initial release by `DB-038`: manual contributions are goal-only; linked incoming transfers are existing ledger movements; withdrawals create linked expense transactions and reduce the goal; void/reversal restores its saved balance. |
| Q-007 | What is the policy for discarding/cancelling import batches? | Resolved by `DB-034`: unfinished workspaces can be discarded and made read-only; history and source bytes remain until the approved 90-day expiry cleanup. Finalized batches cannot be discarded. |

The earlier entries for planning, analytics and forecasting were stale: budgets, savings, subscriptions, analytics, local forecasts and forecast evaluation now exist and have tests. The former OW-010 is resolved: budget plans load into the template editor; account-list CSV/Excel rows are reviewed in Accounts and safely create new KES accounts, with account numbers ignored, duplicate pairs and unsupported currencies excluded. Tests cover dated balances and classification of dated account lists versus statements. These are not open issues; broader release verification remains.
